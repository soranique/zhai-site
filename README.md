# 神诞斋期版本对照

江南周期性神诞持斋研究的可视化网站：以神明为单位，对照各版本斋期表（《玉匣記》等）的记载，与实践记录、《申报》、风俗志的叙事史料。

页面：

- **概览**：数据规模、斋历版本（按年代）、实践记录最多的神明
- **版本对照**：数据库神明 × 全部斋历版本的矩阵，并列叙事史料条数，可搜索、筛选、排序
- **诸本对照**：「玉匣記及其他斋历：版本横向对比」工作簿中的全部版本，逐条对照：版本目录、神明 × 版本矩阵（标出与多数版本不同的日期）、每位神明在各版本中的原文、每个版本的全部条目；数据在 `editions-data.js`
- **斋期日历**：任选最多 4 个斋历版本，按月排列神诞与斋日，并列实践记录；鼠标移到神名上，同一神在各列一起高亮；有实践记录对上的条目在神名后加绿点（存在偏差为黄点）
- **实践与斋历**：实践记录与斋历条目逐条对上的部分（研究者核定的「贴合」「存在偏差」），可按关系筛选、搜索
- **环形历**：任选一个斋历版本（下拉选单，默认《同善錄》正心致福齋期），把全部神圣日排成农历年的历盘（十二月 × 三十日），按「编码日期类型」着色，附出处构成（有出处的版本）、十斋日检验与一神多日；网址 `#ring/版本目录编号` 可直接打开某一版本
- **流通地图**：《玉匣記》的刊刻地、抄写或购得地，与版本家族（共用序文、校者署名、版心）示意；据工作簿已录版本与三浦國雄 2002 的著录（未目验）。资料在 `tools/spread/spread_sources.json`，改后运行 `cd tools/spread && npm install && node build_spread.mjs` 重新生成 `spread-data.js`
- **版本亲疏**：已获完整文本的版本按条目内容比较：重合度网络（横轴年代、纵向文本类型）、共有的少数日期、有依据的先后关系、重合度矩阵、道藏本条目的保留；数据由 `python3 build_kinship.py 玉匣記版本对比.xlsx` 生成 `kinship-data.js`（计入哪些版本、分道、先后关系等设定写在脚本开头）
- **神明档案**：单个神明在各版本中的条目、经典核查、实践记录、《申报》与风俗志；条目与实践记录互相链接（网址 `#g/ZS005/P0070` 直接跳到该神的某条实践记录）
- **缺口**：自动统计的待做事项

右上角「EN／中文」按钮切换中英文界面，选择会记在浏览器里；网址加 `?lang=en` 可直接打开英文版（如 `https://soranique.github.io/zhai-site/?lang=en#ring`）。英文版的规则：

- 人名、神名、地名、书名不翻译，写成「拼音 汉字」，书名拼音为斜体（如 *Yuxiaji* 玉匣記、Guanyin 观音）。拼音由程序自动生成，难免有分词或多音字错误，发现后在 `pinyin_util.py` 的 `FIX` 里补一条再重新生成数据即可。
- 编码取值（证据强度、时段、D/A/C/B 等）给出英文；农历日期写成「月/日」（如 6/24）。
- 研究笔记、摘要、原文引文保持中文。
- 界面文字在 `index.html`、`ring.js` 里以 `L('中文', 'English')` 成对书写；编码的英文在 `i18n.js` 的 `CODES`。

下一步研究方向见 [研究方向.md](研究方向.md)。

## 更新数据

持斋研究数据库更新后：

1. 在 Excel 或 WPS 里打开数据库并保存一次（这样公式格子才有值）。
2. 运行：`python3 build_data.py 持斋研究数据库.xlsx --no-quotes`（`--no-quotes` 去掉原文摘录，公开网站用这个）（需要先装：`pip install openpyxl pypinyin opencc-python-reimplemented jieba`；后三个用于英文版的拼音，没装也能运行，只是英文版不显示拼音）。
3. 把新生成的 `data.js` 上传到这个仓库，替换旧文件。

### 数据来源

- **斋历**：只有一个来源，即「玉匣記及其他斋历：版本横向对比」工作簿（加了新版本页、改了条目后重新生成）。版本对照、诸本对照、斋期日历、环形历、神明档案里的斋历部分都读它生成的 `editions-data.js`：

```
python3 build_editions.py 玉匣記版本对比.xlsx
```

- 跨版本对齐用工作簿自己的「建議規範名（對比用）」。
- 与数据库神明 ID 的对应写在工作簿「神明总表」：「斋库神明ID（ZS）」栏是核对过的；空着时用「斋库神明ID（候选·待核）」栏（程序按名称／异名完全相同给出），网站标「待核」。
- **两套神明编号，不要混用**：斋库神明 ID 写作 `ZS###`（如 ZS008 三官；2026-10-29 以前写作 G###，号码不变），是持斋研究数据库「神明」表的 ID，用来连接实践记录与斋历；神明编码写作 `G####`（如 G0303 元始天尊），是研究者自己的神明编码，在神明总表「神明编码（G####）」栏，网站只作显示。
- 实践记录与斋历条目的对应写在数据库「实践记录」表：「对应斋期表条目ID」（工作簿条目ID）、「对应关系」（贴合／存在偏差／存在偏差（无对应条目）／不对应／待查／待确认删除）、「对应说明」。网站只连接有条目ID 的「贴合」与「存在偏差」。
- 「性質」栏（按神填）目前网站未用；填好后环形历可改按道、佛、地方、儒着色。
- 各版本页的「条目ID」栏（版本目录编号＋序号，如 `03-0123`）是固定值，新录入的行要自己补。
- 「神明认定备注」「总表核对」两栏是内部批注，不输出；资料来源含「識典」的版本不输出原文。
- 持斋研究数据库的「斋期表条目」已并入工作簿（報恩論、玉历钞传警世两页；道藏本 1607 工作簿原已有；众喜粗言没有日期，不并入），网站不再读它。

**神明、实践记录、《申报》、风俗志**：来自持斋研究数据库，由 `build_data.py` 生成 `data.js`。

改了 `data.js`、`editions-data.js`、`ring.js` 等文件后，再运行 `python3 stamp_versions.py`：它给 `index.html` 里的文件地址加上版本号，读者的浏览器才会取新文件，而不是沿用缓存的旧版。

不会运行程序也没关系：把新的 Excel 交给 Claude，说「更新网站数据」即可。

本仓库不包含 Excel 数据库本身，公开版也不含数据库的原文摘录。「已核对原书」目前全部为「否」：原文摘录多据电子文本或资料库全文，引用前请核原书。
